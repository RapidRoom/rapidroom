# Daily upstream sync

The policy decided on 2026-10-13 is **“Ask me first” for any rendering change**. This supersedes the 2026-10-06 policy. The daily sync never records, commits or re-blesses a render reference.

`.github/workflows/upstream-sync.yml` runs at 09:23 UTC or on demand. The repository secret `UPSTREAM_SYNC_TOKEN` is configured. Do not dispatch the first sync until integration PR #179 has merged; the workflow also checks that prerequisite and stops without syncing until then.

1. An open sync PR labelled `needs-human` or `rendering-change` is preserved: later runs cannot overwrite its branch while a human reviews it.
2. Otherwise it merges upstream `main` into a fresh `upstream-sync` branch based on RapidRoom `main`. No new commits: stop. A lone `src-tauri/Cargo.lock` conflict is resolved mechanically: a pre-merge copy of the resolver starts from upstream's lock, then runs `cargo +<toolchain> update -w --manifest-path <absolute merged manifest>` from `RUNNER_TEMP`. The toolchain version is read and installed with `rustup toolchain install --profile minimal` before the merge, so neither merged toolchain files nor merged Cargo configuration can select executables. If the channel cannot be read, the empty value is passed only to the resolver, which refuses it; clean merges still proceed. `GH_TOKEN` is scoped only to steps that call `gh` or push and is absent from the merge/resolver step; checkout does not persist credentials. No generated frontend files are regenerated here; clean-merge staleness remains a gate concern. Any other conflict or a resolver failure aborts the merge and keeps today's behavior: update one `upstream-sync` / `agent:codex` issue, including the resolver's failure output, so an agent can resolve it in a separate PR. The push step runs `gh auth setup-git` after resolution, allowing clean and resolved pushes as well as the gate's base-advance push.
3. A clean or mechanically resolved candidate opens or updates a PR. The unchanged `gate.sh` checks the **exact head and base** against every required hosted workflow: application build (`pr-ci.yml`), production CSP, Frontend Lint & Format, cargo fmt, cargo clippy, Headless CLI exit codes, Vitest, and regression. Applicable MCP-client and change-list checks are gated too. Every required job must succeed; skipped jobs are not success (apart from the change-list workflow's non-PR refresh job).
4. A missing, failed, cancelled or timed-out required check blocks merging. Only a diff that provably excludes a recognized workflow path filter permits an absent regression/MCP/change-list run. Unknown filter syntax fails closed. A successful regression run must have successful determinism **and comparison with the committed reference** steps; merely uploading a newly recorded reference is insufficient. The candidate cannot change that reference.
5. **Any render comparison or determinism failure:** keep the PR open and label it `needs-human` + `rendering-change`. Create/update an issue assigned to the maintainer, linking the `regression-diff` artifact with before/after panels and reports (14-day retention). The regression job renders the checked base for the before images, verifies it against its committed reference, and produces panels for differing cases. If evidence generation fails, its logs explain what is missing; the PR remains blocked until evidence and human approval are obtained.
6. **All required checks pass and rendering is unchanged:** recheck head and main immediately before `gh pr merge --match-head-commit`. A changed head blocks merging. An advanced base is merged into the candidate with a lease-protected push, then **all checks are required again for the new head/base**. Repeated base advances or conflicts leave the PR open. No `--auto` merge is queued. After merging, the actual merge commit's first parent is compared with the verified base. A mismatch opens a `needs-human` issue and dispatches the complete hosted check set on main.

Other failures leave the PR open labelled `agent:codex`, with the checked head/base and reason. The gate polls at five-minute intervals and has a five-hour total deadline, including base refreshes. This conditional daily-sync merge is the only automated exception in AGENTS.md; rendering changes still require explicit human approval through the normal review/reference process.

## Sync agent and reviewer (2026-10-29)

The workflow merges only clean syncs whose renders are unchanged. Everything else goes to the sync agent, a Claude Code cloud routine (Sonnet) that runs every four hours and acts as a maintainer account. Each run takes the next step for any open sync work and stops; the state lives in the PRs, issues, labels and comments. Since 2026-10-29 the sync agent does not review its own resolution. A separate read-only sync reviewer routine (Opus) posts the review comment. The merge workflow accepts only that comment.

- **Conflicts:** it resolves them on `sync/upstream-<date>` and opens a PR that closes the conflict issue. Both routines follow the prefer-upstream rule: when functionality is similar, take upstream's version. Both also follow the locale-overlay rule (`#477`): take `src/i18n/locales/<lang>.json` from upstream byte-for-byte and keep RapidRoom strings only in the overlay. See [Locale catalogs](#locale-catalogs).
- **Sign-off:** the sync agent pre-reviews the resolution with a subagent, then posts `Sync sign-off requested at <sha>`. It never posts a comment that starts with `Sync review:` (self-approval is blocked). That sign-off comment does not match the merge workflow.
- **Review:** the read-only reviewer reviews the merge against both parents and posts `Sync review: FINAL ACCEPT at <sha>` or `Sync review: not accepted at <sha>`.
- **Upstream render changes:** under the maintainer's standing approval (2026-10-23), the sync agent records a new `ci-reference.json` with `regression.yml` (`record=true`) and commits it. This applies only when upstream commits in the sync change rendering code, the resolution keeps upstream's render logic as is, and the diffs match that change. Any other render change, or any doubt, keeps the PR held: `needs-human` + `rendering-change` plus a `Sync agent: holding for the maintainer` comment that mentions the maintainer.
- **Merge:** neither routine merges. The sync agent's tool permissions refuse the merge call. `.github/workflows/upstream-sync-merge.yml` starts on an issue comment by yojen7 whose body starts with `Sync review: FINAL ACCEPT at `. `rapidroom/upstream-sync/merge-reviewed.sh` merges a `sync/upstream-*` PR into `main` only when the latest comment by yojen7 (`SYNC_REVIEWER`, default `yojen7`) whose body starts with `Sync review:` matches `^Sync review: FINAL ACCEPT at ` and a 40-character hex sha. A later `Sync review:` comment that does not match, including `Sync review: not accepted at <sha>`, blocks the merge. That sha must cover the exact head, `main` must already be in the head, the head must still have `ci-reference.json`, and the PR must not be held (`needs-human` or `rendering-change`). "Covers" means every commit after the reviewed one is a clean automatic merge of `main` (its tree equals what `git merge-tree` produces, so a hand-edited merge fails), a change-record-only commit, or a reference re-record whose message carries the standing-approval sentence. Checks use the daily gate's rules from `gate.sh`: each required workflow needs its latest `pull_request` run for this PR, head and base, every required job must pass, and regression must pass its determinism and reference-comparison steps; a path filter excuses a workflow only when the diff provably avoids it. A cancelled required run blocks until it is re-run. Every run checks every open sync PR; it runs when a review comment is posted, when a required workflow finishes on a sync branch, hourly and on demand. It rechecks the head, `main` and the labels right before `gh pr merge --match-head-commit`, verifies the merge commit's first parent like the daily gate, and deletes the branch. An unexpected error labels the PR `needs-human` once. The maintainer approved this on 2026-10-28.
- **Never:** the sync agent never posts `Sync review:` comments, pushes to `main`, re-blesses a RapidRoom-caused render change, or merges with a check missing.

The routines' prompts are kept with the maintainer's project notes. Pause them at claude.ai/code/routines.

## Locale catalogs

Take `src/i18n/locales/<lang>.json` from the upstream merge parent byte-for-byte, including formatting. Do not resolve these files by combining RapidRoom strings into them. RapidRoom additions and overrides live in `src/i18n/locales/rapidroom/<lang>.json`, deep-merged over upstream by the small hook in `src/i18n/index.ts`; the overlay wins. Keep the overlay files and merge hook when syncing.

New RapidRoom strings, branding changes and completed plural forms belong only in the overlay. `npm run i18n:extract` reads the complete merged catalogs in temporary files and writes only differences back to the overlay. After a sync, run `npm run i18n:check`, `npm run i18n:runtime-check`, and the locale-loading Vitest; if upstream adds or changes a key, retain any intentional RapidRoom override. The migration receipt and reproducible checker are in `rapidroom/validation/420-locale-overlay-migration.json` and `rapidroom/validation/check-locale-overlay.mjs`.

## Remaining base race

Main deliberately keeps the [non-strict status policy](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches) to avoid forcing all parallel PRs to refresh and repeat long CI after every merge. GitHub binds the merge to the expected head, while our last base read and the merge are separate requests. A seconds-wide base race remains; the post-merge first-parent check detects it and escalates to human review plus full hosted checks on main. The workflow does not silently claim that combination was verified, roll it back, or re-bless a reference.

## Token and maintenance

Use a fine-grained token limited to **RapidRoom/rapidroom**, owned by a maintainer, with read/write **Contents, Pull requests, Issues, Actions and Workflows**, and an expiry of at most 366 days. Store it as `UPSTREAM_SYNC_TOKEN`; renew before expiry. A missing/expired token fails closed. The built-in `GITHUB_TOKEN` cannot push upstream workflow commits or trigger the PR checks.

When required workflows, job names or path filters change, update `rapidroom/upstream-sync/gate.sh` and its mocked tests together. Local validation: `bash rapidroom/upstream-sync/test-gate.sh`, Python panel tests, and actionlint. These do not invoke GitHub, render photos, merge a PR or dispatch the live daily sync.

# Photo packets, reusable presets and metadata-only imports (#218)

A photo-sidecar packet with the image subject's `AlreadyApplied=True` says its development settings already exist in the image pixels. RapidRoom skips those development values, including curves, crop, lens and masks, while still importing supported rating, label and tags. Metadata-only outcomes preserve the development object exactly, including null; ratings update top-level metadata rather than being inserted into preserved adjustments. This policy applies to RAW, DNG, JPEG and TIFF photo contexts without inferring process or enhanced-DNG exceptions from filenames. Foreign namespaces, nested looks and other RDF subjects cannot turn the flag on. False or an absent flag retain ordinary import behavior.

Reusable presets carry editing instructions rather than baked pixels. Their development values remain reusable even if the source packet has AlreadyApplied=True. This is an explicit import-context distinction, not a claim of Adobe rendering equivalence.

Metadata-only imports preserve saved adjustments and the current active draft. The frontend cancels the queued autosave rather than flushing it into the incoming XMP; it holds a sustained save pause while waiting for every write already started and throughout the import. A failed started write is reported only after the other started writes settle. New save requests are buffered by photo, the pending history entry is retained, and the live draft is passed to the importer. Supported development imports replace the draft and reset history as before; metadata-only outcomes do neither. Folder results distinguish adjustment imports from metadata-only imports and report already-applied packets. Cancelling file selection or a failed import resumes the newest live draft rather than the earlier snapshot. New edits made while an import is pending also survive a successful import; buffered saves resume afterwards.

Single/folder import commands read XMP without synchronizing metadata back to that input. The exact normalized draft applied from a completed import is marked persisted so the renderer's autosave echo cannot start an unnecessary input-sync write; a subsequent new edit uses ordinary autosave. Ordinary user-enabled autosave XMP sync remains separate: an already-running save may complete its normal sync before the import reads the file. The preparation step does not cancel that in-flight write or claim to recover earlier input bytes.

Focused Rust tests cover flag/context/namespace/subject behavior and preservation of adjustments, pending curves/masks/lens edits, metadata and input bytes. Frontend tests exercise the public context-menu actions, history outcomes, queued versus already-running saves, cancellation and folder results. The native `--xmp-photo-policy` fixture uses a disposable CC0 copy and synthetic XML with ordinary XMP sync enabled, checks public single/folder imports while a slider autosave is pending, exact Undo restoration, ordinary False/absent packets, and real preset import plus the public preset browser. Its actual results must be inspected before claiming a pass. No model requests, Adobe application test, private photo upload or enhanced-DNG exception is included.

The older four diagnostics concern adjustment-group translation labels, panel
switcher translation labels and the virtualized Culling/Library rows. They
already exist in the first parents; later #45 slices remove that debt. The
latest tree's remaining diagnostic is the catalog import's arbitrary-string
source label. Its backend already defines the five `DevelopValueSource`
variants. Giving the frontend the same union removes this diagnostic without
changing runtime behavior; both the latest sync and its first parent then
report zero errors.

A historical hard-zero gate would have rejected those trees because of existing
debt. None of these five syncs adds a diagnostic, so this sample does not show
recurring TypeScript breakage from upstream. With the current source-label fix
reaching zero, CI uses a strict `npm run typecheck` gate. ESLint remains a
separate no-new-errors ratchet, as it still has substantial existing debt.

This is a source/typecheck audit, not native UI or rendering validation. It does
not promise that a future upstream change cannot introduce a type error.

# Offline mode: design and evaluation

Issue #261, design only. Source inventory: `271c9ed2b7c83900bad8210c34bfb962cbf227ae` (2026-10-14). **Offline mode is not implemented by this document.** The current app can make requests on library startup and when using the features below. No network capture or offline runtime certification accompanies this proposal.

## Scope and decision

Add a persisted app-wide Offline policy before offering an “Offline” indicator. While active, RapidRoom must not initiate remote network requests, including DNS, background checks, embedded resources, downloads, or requests to AI providers. Local editing, import/export, installed presets and verified local models remain available. No cloud preference is deleted, no network endpoint is added, and no system firewall is changed.

An optional user-launched assistant, shell command or external browser has its own network behavior. Offline mode cannot make those programs offline. OS-managed NAS access, placeholder hydration, cloud-sync clients and camera drivers also need a separate boundary: the supported offline workflow uses files already present on local storage. Do not describe this setting as an air gap or firewall.

Prior art is RustRunner/RapidRAW-MKII commit `555f7c6ddd5b6b5d219f87e3552a334968e9ddd9`, identified by the issue. This proposal does not copy its code or remove Community, maps, updates or Cloud from online sessions.

## Persisted policy and transitions

Proposed storage: a versioned `network-policy.json` beside the per-user settings returned by `app_config_dir`, separate from ordinary `settings.json` resets/imports. This filename and schema do not exist yet. Rust owns the policy; frontend state is a read-only projection plus explicit change commands. Persist with an atomic same-directory replacement and report write errors before showing a successful change.

| Stored state / action                                                          | Proposed behavior                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No policy file on upgrade                                                      | Preserve current online behavior; this proposal does not opt anyone into a new service. Offer Offline in Settings.                                                                                                                                                                                                                                  |
| Valid Offline policy at startup                                                | Load before spawning request-capable tasks, constructing SDKs, opening the WebView or restoring panels. Show Offline only after backend and WebView guards are installed.                                                                                                                                                                           |
| Unreadable, malformed or unsupported policy version                            | Fail closed for app-owned network and show `offline-policy-unreadable`. Local editing remains available. Explain recovery; never silently default to online.                                                                                                                                                                                        |
| Enable Offline during an online session                                        | Immediately prevent new app-owned work, cancel queued/running requests and persist the request. Show **“Offline pending restart”**, not “Offline”. Existing frames and already sent bytes cannot be recalled. Complete a normal app restart; only the guarded new session satisfies the claim. Preserve unsaved work through the normal close flow. |
| Disable Offline                                                                | Explain which checks/downloads/maps/providers may connect, then require explicit confirmation and successful persistence. Apply on restart. No queued actions replay automatically; Cloud and assistant opt-ins remain unchanged and require their existing consent.                                                                                |
| Cancel restart, persistence failure or restart failure                         | Report the actual state. Keep the current session's deny-new-work guard after an enable request; preserve the pending choice for the next successful launch. Do not claim a completed transition.                                                                                                                                                   |
| Reset settings, restore workspace, imported config, MCP edit, background retry | Cannot re-enable networking or overwrite the separate policy. Only the explicit consent command changes it. Re-check policy when executing a job, not just when enqueuing it.                                                                                                                                                                       |

The backend must guard every network-capable command, not only disabled UI controls. Proposed refusals are structured codes with a feature/asset identifier and a safe user message, never tokens, full source paths or prompts. `offline-network-disabled` covers checks, Community, maps and providers. No refusal schedules a retry or recommends disabling protection automatically.

The implementation must prove early WebView enforcement on Linux, Windows and macOS before claiming support there. If a platform cannot enforce it, report Offline unavailable on that platform instead of displaying a weaker guarantee under the same name. Any future direct socket, SDK or dependency change must update this inventory and its tests.

## Verified local models and import

Current discovery is `app_data_dir()/models` through `get_models_dir`. The generic initializer eagerly prepares SAM encoder/decoder, U2Net, SkySeg and depth together; it can download an unrelated missing asset before using a requested operation. Split this into feature-specific resolution so one absent model does not prevent an otherwise supported local operation. Preserve the verified legacy SkySeg filename promotion.

| Asset family                                                                   | Current integrity anchor / gap                                                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SAM ViT-B encoder + decoder; U2Net; SkySeg; depth-anything-v2-vits; NIND; LaMa | Filename and SHA-256 constants in `src-tauri/src/ai_processing.rs`. Use these exact contracts, not similar upstream model names or alternate exports.                                                                                                                                                            |
| CLIP                                                                           | Model SHA-256 is pinned, but `clip_tokenizer.json` is currently downloaded on absence and parsed without a pinned digest. Offline support for tagging is blocked until the tokenizer identity, model compatibility and redistribution terms are recorded. Do not accept arbitrary JSON merely because it parses. |
| TreeNet Best/Fast + optional DeepSharpen                                       | Files and SHA-256 in `src-tauri/src/tree_denoise.rs`. Existing provenance/limitations are in [DENOISE.md](DENOISE.md), including the absence of a separate checkpoint license grant. Preserve this distinction.                                                                                                  |
| ONNX Runtime                                                                   | Packaged platform artifact and SHA-256 in `src-tauri/build.rs`; local model import must not download or replace executable runtime libraries.                                                                                                                                                                    |

Proposed local import uses a file picker, never a URL or archive extractor. Match a bundled registry entry containing asset ID, exact SHA-256, size bounds, filename, required tensor names/types/shapes, preprocessing/postprocessing version, companion assets and license/provenance references. Reuse the current operation contracts; changing a model or renderer is outside #261. Hash a bounded staged copy, validate its contract before loading for normal work, then atomically install that verified copy. Hash and use the same bytes to avoid source-file replacement races. Do not execute scripts, fetch manifests/licenses, follow unbounded symlinks or overwrite a working model on failure.

Discovery and import should return these proposed outcomes with no network fallback:

- `offline-model-missing`: exact required file or companion missing; name the local import action.
- `offline-model-integrity`: wrong digest, empty/truncated file or invalid size; preserve the user's original and existing good cache.
- `offline-model-contract`: incompatible tensors, tokenizer or preprocessing contract; do not try another provider/model.
- `offline-model-license-unverified`: no reviewed license/provenance record for these exact bytes. A hash proves identity, not permission, and a code repository license is not automatically a weights grant.
- `offline-model-runtime-unavailable`: packaged runtime/provider unsupported; keep ordinary editing available.

Before allowing each asset family, retain a reviewed license/provenance record in the repository and bundle the required notices. This document does not newly approve any model license, redistribute weights, or claim that all current cached files satisfy that future registry. Unknown assets remain unavailable. Avoid adding a “trust any file” override as a shortcut.

## Implementation sequence and exit criteria

1. Review this contract and inventory; settle supported platforms and per-model provenance gaps. Keep this issue scoped to design/evaluation; create implementation issues with explicit ownership.
2. Implement backend policy/bootstrap and centralized guarded HTTP clients, including provider probes/retries and direct command/MCP paths. Implement verified WebView resource blocking and restart transitions. No new endpoints or telemetry.
3. Implement feature-specific verified local resolution/import and named refusals. Preserve existing online behavior and consent outside Offline.
4. Execute [OFFLINE-VALIDATION.md](OFFLINE-VALIDATION.md) on each claimed platform and publish sanitized receipts bound to the exact source/binary. Until then, Offline remains unimplemented/unverified.

All runtime changes still require the normal local/hosted checks, review and native evidence. Engine changes also need their rendering gates. A document merge does not waive them or authorize network additions, model redistribution, new firewall rules, deletion of Cloud preferences, or a release claim.
